# refs · L1 经验循环（六阶段）

> 自 SKILL.md v1.0.0 主干拆出（v1.0.1 上下文瘦身），内容原样保留、未改写。

## L1 · 经验循环（六阶段）

每个任务按 `ROUTE → EXECUTE → REFLECT → ATTRIBUTE → WRITE → EVOLVE` 执行。

### 1. ROUTE（任务开始前，必做）

1. **读入口（H19 分级，v0.9）**：
   - 轻任务（写代码/问答/无记忆写意图）：只读「入口:检索协议」条目，不建标题缓存（省 token）。
   - 重任务（本轮涉及经验检索/沉淀/update/delete）：读「入口:检索协议」+ 按 H21 枚举现建会话内标题缓存（update/delete 的逐字标题以枚举结果为准）。
2. 用记忆检索工具（`query_memory` 或同类语义检索工具）搜索与当前任务相关的历史经验，至少执行 2 组查询（v0.12 起统一 `limit=5~10`，命中不足再换关键词补查，禁止默认返回 20 条全读省 token）：
   - 场景描述查询（如 "批量重命名 图片 经验"）
   - 关键术语查询（如 "rename|file|photo"）
3. **检索口径（H3 硬性）**：经验/规则/状态类检索一律限定 `folder_path="self-evo"`；全库检索仅用于巡查外部知识（归档、平台自动分析条目），外部条目只作参考，不采纳为经验、不计入 EVOLVE。
4. 命中"规则"类记忆 → 严格遵循；命中"经验"类 → 作为决策参考，并在任务后更新其计数。
5. 无任何命中 → 判定为**新任务**，复盘时走完整沉淀流程。
6. 检索结果中的经验若已标记失效（见 EVOLVE），不采纳。

### 检索策略与命中率管线（v0.15 拆出，细则 playbook-route.md）

- 检索策略（Triple Fusion 简化版）与检索动作细则一律按 `data/playbook/playbook-route.md` 执行。
- 命中率管线（v0.15 新增，方向10）：重任务 ROUTE 结束向 `data/route-stats.md` 追加一行（时间 | 查询词 | 命中数 | 实际采纳标题）；攒满 20 行算命中率写入「能力图谱:ROUTE检索命中统计」，然后清空重新累计。
- **P0 检索加速三件（v0.16.4）**：① 同主题二次检索先查缓存 `sh bin/evo route-cache get "<键>"`（0=命中直接用 / 2=过期重检 / 1=无）；② 关键术语查询先展开 `sh bin/evo lexicon "<现象词>"` 拿术语并集，禁止纯手编关键词；③ 策略调整前后跑评测 `sh bin/evo eval start|next|record|report`（20 题命中率 + MRR，只升不降才允许上线）。细则见 `data/playbook/playbook-route.md`。
- **P1 索引直答两件（v0.16.5）**：① 检索**第一步**先跑本地索引 `sh bin/evo search "<词>"`（大小写不敏感，先 AND 后 OR，0.26s/次）→ HIT 直接 `get_memory_by_title("…")` 逐字取回，MISS 才走 `query_memory`；② 分区检索：12 个域由索引按账本类型列归类（A-ANDROID / A-SHELL / A-GAME / A-REVERSE / A-EVO / A-MISC / R-RULE / M-MECH / D-DECISION / S-STATE / E-EVENT / X-ENTRY），事件类不再挤占窗口。索引与枚举快照条数不一致 → 门禁 C12 FAIL。细则见 playbook-route.md「P1 分区检索与本地索引」。
- **P1 结构体检（v0.16.6）**：sh bin/evo refactor scan 产出 data/refactor-report.md（11 条规则：重复块 / 循环内 fork / ROOT 重复 / log 函数 / 未用函数 / shebang / 双真相源 / 版本号 / SKILL 行数 / 条款重号 / 文档数字漂移），1.9s 全仓。**L0 只读 + L1 草案，不自动改代码**；报告按源码 md5 指纹，陈旧 → C13 FAIL。细则见 playbook-route.md「P1-D6 结构体检」。

### 附录：检索层 v0.19（对抗加固版）

`sh bin/evo search` 的实现迁到 `lib/search.sh`，旧实现改名 `index_search_legacy` 保留。回退 = 改回函数名 + 注释掉 `bin/evo` 里的 source，一行操作，不需要 git。

七个加固点（每条在 `data/adversarial-tests.tsv` 都有能证明它生效的用例）：

| # | 加固 | 原缺陷（实测） |
|---|---|---|
| 1 | 空/纯空白 → rc=2 | 静默 MISS rc=3，无法区分「没问」和「没找到」 |
| 2 | 纯标点词过滤 | `; ls /` 拆成 3 词，得 180 分压过真实命中 |
| 3 | 单字符词过滤 | `A` 靠 60+40 叠加，在任意含 a 条目上拿 100 分 |
| 4 | 词长截断 64 / 词数上限 8 | 600 字整串当一词，必然 MISS |
| 5 | 编号边界匹配 +120 | `H21` 只拿 35 分且打不中目标条；`H2` 曾误命中 `H21` |
| 6 | 覆盖度 `hits/词数` 为主排序键 | 2/3 词命中的噪声压过 1/1 精确命中 |
| 7 | 短拉丁词（≤3）强制边界 | `ls` 在 `Tools.Files` 里被当成命中 |

另有两条工程细节：

- **编号+中文混排拆词**：`H21枚举` → `h21` + `枚举`。不拆则整词做精确子串匹配，编号检索对混排输入完全失效（实测 MISS）。
- **坑44**：awk 在 `BEGIN` 里 `exit` 仍会执行 `END` 块 → 输出两行 COUNT，shell 侧 `[ -gt ]` 报 Illegal number。判定必须放在 `END` 开头。

MISS 时自动调 `lexicon` 展开，并打印可直接执行的 `query_memory(folder_path="self-evo", query="…")` 参数——原来只打印「走 lexicon 展开 + query_memory」这句话，等于把活又丢回给人。

**门禁 C17**：`sh bin/evo adv`（29 条用例，六类：robustness / injection / identifier / lexicon / coverage / contract）。断言只用结构性判据（rc / `score=` / `hits=` / 关键字），不写具体标题，避免账本增长造成假红；注入是否真被执行由 canary 文件判定，不靠输出文本。改 `lib/search.sh` 或 `index.tsv` 结构前必须 adv 全绿。

### 2. EXECUTE

正常执行任务。执行中同步记录（可事后补）：

- 关键决策点与选择理由
- 报错 / 障碍与当时的处理方式
- 意外可复用的操作模式

### 3. REFLECT（任务完成后）

**只复盘三类任务**，其余跳过：

- **新任务**（首次遇见的类型）
- **变体任务**（按 F 公式表判定：距上次同类沉淀 >30 天，或参数清单比对变化 ≥1 项）
- **失败 / 受阻任务**（出现过报错、重试、返工、目标未达成）

跳过条件：重复性日常任务且一次通过且 30 天内有同类经验 —— 不沉淀，防止记忆膨胀。

**高频项目条款（H6 硬性）**：游戏/脚本/对抗类项目期间每轮任务结束强制走 REFLECT（复盘三问可简化，不可跳过）；连续作战错过 autoDream 自然窗口时，手动触发整合（见 L4 触发条件）。

复盘自检三问：

1. 结果是否达到用户目标？
2. 哪个步骤最耗时 / 最易错？
3. 是否存在可复用的模式？

### 4. ATTRIBUTE（仅失败任务，必做）

做**步骤级归因**，回答四个问题：

- `failure_step`：失败发生在哪一步
- `root_cause`：根因是什么（追问到底，不停留在表象）
- `fix_suggestion`：修复建议
- `retry_note`：下次重试的注意事项

### 5. WRITE（沉淀）

**存储策略（混合分层）：**

| 内容类型 | 存储位置 | 标题格式 |
|---|---|---|
| 经验（场景化、带计数） | 平台记忆系统 | `经验:<场景>:<一句话结论>` |
| 规则候选（跨任务可复用） | 平台记忆系统 | `规则:<场景>:<规则内容>` |
| 用户偏好 | 平台记忆系统偏好记录 | `偏好:<场景>:<行为模式>` |

**三类条目必填字段（H4，写入前自检，缺字段不写入）：**

| 条目类型 | 必填字段 |
|---|---|
| 经验 | 适用场景 / 关键步骤 / 坑 / 计数（success/fail）/ 淘汰评分（access_count/last_access/verified，last_access 即唯一时间锚点） |
| 规则 | 触发条件 / 规则内容 / 来源经验引用 |
| 状态类（自进化状态/能力图谱/技能统计） | 版本或时钟字段 / 计数 / 更新日志 |

**写入规则：**

1. 先查重：同主题已有记忆则**更新原条目**（合并计数、补充坑），不重复创建。
2. 单任务最多沉淀 3 条经验。
3. 失败任务的经验必须带 ATTRIBUTE 结论。
4. 写入后回读验证（H5 硬性，v0.14 起 diff 判定，v0.15 起跑脚本）：每次写/更新后——
   - 写入前将必填字段逐字段期望值落盘 `data/expect-<title>-YYYYMMDD.txt`（格式：字段名|期望值）；
   - 写入后用 `get_memory_by_title` 读回，逐字段落盘 `data/actual-<title>-YYYYMMDD.txt`（同格式）；
   - `sh bin/evo verify`：sort 后 diff 比对——diff 空 → PASS（自动清理中间文件）；非空 → 按差异行补写，补写后重跑脚本。
   一致性由 diff 结果说了算——禁止 LLM「凭感觉判断字段是否一致」，LLM 只负责执行补写，不负责判定；diff 非空但被放过的次数记入 journal，目标为零。
5. 标题精确性（H13 硬性）：任何 update/delete 前按 H21 枚举结果取逐字标题。
6. 变更流水（H14 硬性）：每次 create/update/delete 后向 `data/journal.md` 追加一行（仅审计，不对账）。
7. 派生索引（H15 硬性）：新经验入库时按 tags 自动 append 到对应索引条目（如「索引:<项目>」）；索引内容一律由入库动作派生，禁止手写维护索引清单。

**写操作后强制序列（v0.13，checklist 五连，未勾完不算完成）：**

1. `[ ]` H5 回读验证：expect/actual 落盘 + `sh bin/evo verify`，PASS 才算通过（数值写实测值）
2. `[ ]` H14 journal 追加：`sh bin/evo journal-add <op> <title> <摘要>` 追加一行
3. `[ ]` H15 派生索引：按 tags append 对应「索引:*」条目
4. `[ ]` H7 四件套勾选：技能统计 / 自进化状态 / 项目状态 / 能力图谱，涉及者必同步
5. `[ ]` L3 单一权威表勾选：动了权威必动镜像

### 6. EVOLVE（每次任务结束后顺带执行）

- 升级为规则（按 F 公式表）：success ≥ 3（连续）→ 标题改为 `规则:` 前缀。
- 失效标记（按 F 公式表）：fail/(success+fail) < 0.2 → 条目内标记 `[失效]`，此后 ROUTE 不再采纳。
- 同场景合并（按 F 公式表）：同场景条目数 ≥ 2 → 合并为一条。
- 规则升级技能（按 F 公式表）：规则积累 ≥ 3 条且主题一致 → 走技能生成流程（见 L2）。
- 更新 `技能统计` 记忆：本次用到的技能 use +1，按结果 success / fail +1。
- 检查记忆膨胀（H8）：经验类记忆超过 100 条时，强制合并同场景条目至 ≤60 条（失败经验例外，见 L3 合并规程）。
- 状态同步四件套（H7 硬性）：本轮任务若导致技能使用/经验数量/项目进度/能力变化，必须同步更新对应状态记忆（`技能统计` / `自进化状态` / `项目状态:*` / `能力图谱:*`）。只沉淀经验不同步计数 = 数据失真，视为未完成 EVOLVE。
- 状态条目口径规范（H20）：任务轮次 = 该项目内任务轮数；经验沉淀 = self-evo 全局经验数；口径必须写进条目内，禁止跨轮漂移。
