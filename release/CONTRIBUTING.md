# 贡献指南

## 硬规则

**1. 不得提交任何真实账本**

以下路径永远不进仓库：

```
data/journal.md      （只能提交空模板）
data/store/
data/backup/
data/waters.md
data/route-cache.md
data/route-stats.md
data/eval-runs/
```

提交前自查：

```sh
git diff --cached --name-only | grep -E 'journal|store/|backup/|waters'
# 有输出 → 撤掉
```

**2. 改代码必须过门禁**

```sh
sh bin/evo self-test      # 必须 41/0/0
sh bin/evo check          # 结构门禁
sh bin/evo adv            # 对抗用例
```

PR 描述里贴输出。**"我本地跑过了"不算。**

**3. 零依赖是硬约束**

不许引入：

- Python / Node / Ruby 运行时
- 任何需要 `pip install` / `npm install` 的东西
- 向量库、数据库、网络服务
- 需要编译的二进制

只能用：**POSIX sh + mawk + 系统基础命令**（`grep` `sed` `awk` `find` `sort` `wc`）。

真要加依赖，先在 issue 里论证为什么现有工具做不到。

**4. 明文是硬约束**

不许把账本改成二进制、加密、压缩格式。账本必须可 `git diff`、可人读。

**5. 不做自动提取**

不许加"LLM 自动决定记什么"的功能。写入必须是有门槛的显式动作。见白皮书 D3。

## 提交什么会被接受

| 类型 | 欢迎度 | 说明 |
|---|---|---|
| 修 bug | ✅✅✅ | 附复现命令 |
| 补对抗用例 | ✅✅✅ | **最有价值** —— 你踩的坑就是别人的门禁 |
| 补文档 / 翻译 | ✅✅ | |
| 性能优化 | ✅✅ | 附前后延迟对比 |
| 新检索算法 | ✅ | 必须过双评测集，且不能退化关键词集 |

| 自动提取 | ❌ | 见硬规则 5 |
| 加密 / 混淆 | ❌ | 破坏可审计性 |

## 怎么提一条对抗用例

**这是最有价值的贡献。** 你踩过的坑，应该变成别人的门禁。

格式见 `data/adversarial-tests.tsv`：

```
编号	分类	查询	期望 rc	期望输出片段
A33	arg	查询词 --all	0	[seed
```

提交 PR 时说明：

1. **原始场景**：你在做什么的时候发现的
2. **错误行为**：本该怎样，实际怎样
3. **为什么现有用例没覆盖**

不建议一次提 20 条。**一条真踩过的坑，胜过十条想出来的。**

## 代码风格

- **POSIX sh**，不用 bashism（`[[ ]]`、数组、`local` 都别用）
- 变量一律加引号：`"$VAR"`
- 错误信息 `echo >&2`，正常输出 stdout
- 函数命名 `snake_case`
- 中文注释可以，但**不要写"这里可能有坑"这种废话** —— 写清楚为什么这么写

---

## 提交信息

```
<类型>: <一句话>

<为什么这么改>
<验证方式>
```

类型：`fix` / `feat` / `docs` / `test` / `refactor` / `perf`

例：

```
fix: search 的 --all 参数不再污染查询词

原实现只认 $1，--all 写在后面会被并进 Q，
导致 LIM 保持 5（结果截断）+ n 多 1（覆盖度分母被污染）。
改为扫描全部参数抽 --all，其余重建 Q。

验证：adv A33/A33b 覆盖位置无关性，self-test 41/0/0。
```
