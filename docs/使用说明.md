# EVO自进化 · 安装与使用说明书

> 面向使用者的完整手册。想先看「它是为什么这么设计」→ [`release/WHITEPAPER.md`](../release/WHITEPAPER.md)；想改代码 → [`SKILL.md`](../SKILL.md) 与 [`CONTRIBUTING.md`](../release/CONTRIBUTING.md)。
> 版本：v1.3.1 ｜ 运行期依赖：POSIX `sh` + `awk`（mawk/gawk 均可）｜ 无 Python、无服务、无网络调用

---

## 0. 三十秒版

EVO 不替你记东西，EVO 管你记的东西**还对不对**。

- **账本**：一张 Markdown 表格，明文，可 diff、可回滚、可手工编辑
- **索引**：`store sync` → `index build` 两步生成，检索命中的是索引
- **门禁**：`check` / `self-test` / `adv` / `search-eval` 四道，CI 式守质量
- **循环**：任务前检索经验 → 任务后复盘落账 → 失败步骤级归因 → 经验升规则
- **边界**：不自动提取经验（自动提取 = 不可复现 = 审计归零）

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Shell | POSIX `sh` | mksh（Android）、dash、bash 均可 |
| awk | mawk 或 gawk | **Ubuntu 26 起 `awk` 指向 gawk，字节语义脚本需注意** |
| zip | 仅打包时需要 | Android toybox/BusyBox 无 `zip`，打包要在 proot/Linux 侧 |
| git | 可选 | 只有 `bundle` 冷备与版本管理需要 |

最低可跑环境：任何有 `sh` 与 `awk` 的地方，含 air-gapped 内网。

## 2. 安装

### A. 作为 Operit Skill（手机/Android，最常见）

```sh
SKILLS=/sdcard/Download/Operit/skills      # 你的 Operit skills 目录
cd "$SKILLS"
# 解压发行包（GitHub Release 下载 zip）
unzip EVO自进化-*.zip -d EVO自进化
cd EVO自进化
sh bin/evo version                            # 应打印 root 与 journal 路径
```

Skill 是靠 `SKILL.md` 的 frontmatter 被宿主识别的，**不要改文件名**。

### B. 作为独立命令行工具（Linux / Termux / PC）

```sh
git clone <本仓库地址> EVO自进化
cd EVO自进化
cp data/journal.seed.md data/journal.md       # 载入 10 条示例经验
sh bin/evo store sync                         # ok  store sync: 10 条
sh bin/evo index build                         # ok  index build: 10 条
sh bin/evo search "门禁"                       # HIT n rc=0 / MISS rc=3
```

放到 PATH 里（可选）：

```sh
ln -s "$PWD/bin/evo" ~/.local/bin/evo
evo version
```

> **重要**：源码树里有硬编码的 Android 路径，**不要把源码树 clone 到别的机器直接当成品**。
> 可移植产物请用 `sh release/build-public.sh /tmp/EVO-public` 生成后使用。

### C. 从分发快照安装（跨机器推荐）

```sh
sh release/build-public.sh /tmp/EVO-public
cd /tmp/EVO-public
cp data/journal.seed.md data/journal.md
sh bin/evo store sync && sh bin/evo index build
sh bin/evo self-test
# PASS=30 FAIL=0 WARN=3 —— 3 条 WARN 是「无账本 / 无 git / 无 bundle」，公开快照态属预期，不是故障
```

## 3. 五分钟上手

### 3.1 自检：先确认环境健康

```sh
sh bin/evo self-test
```

判据是 **`FAIL=0`**，不是 PASS 的数量（项数随脚本数变化，不要抄数字）。

### 3.2 写第一条经验

三条通道，按场景选：

| 场景 | 用什么 |
|---|---|
| Operit 插件内（有 `evo_reflect` 工具） | `evo_reflect(kind, target, conclusion)` — **唯一写入入口** |
| 纯命令行 | 直接编辑 `data/journal.md`，追加一行表格 |
| 已有 Markdown 手写笔记 | 同上，列顺序对齐表头即可 |

账本行格式（`|` 分隔，五列）：

```
| 2026-11-18 06:51 | exp | 对象名（≤80字） | 结论（≤400字） | 验证证据（≤200字） |
```

**没有验证证据的条目会落成「未验证」**——不拦你写，但检索与审计时会区分对待。

### 3.3 生成索引并检索

```sh
sh bin/evo store sync      # 账本 → store/journal.tsv（幂等，自带近重复去重）
sh bin/evo index build      # journal.tsv → index.tsv
sh bin/evo search "关键词"
```

返回码约定：`HIT` = 0，`MISS` = 3 —— **可以被脚本直接判定**。

### 3.4 一条命令收尾

```sh
sh bin/evo journal-commit
```

它做四件事：原子锁 → `store sync` → `index build` → 七查一致性。

> ⚠️ **实测行为（v1.3.1）**：若七查发现违规，`journal-commit` 会把违规结论**追加成一条新账本条目**，此时账本会比 store 多 1 条，查 7 仍报「三方不一致」。
> 这是「自检记录滞后一轮」的设计缺陷，处理办法是**补跑一次**：
> ```sh
> sh bin/evo store sync && sh bin/evo index build
> ```
> 之后三方（账本 / store / index）应当等值。

## 4. 日常用法：四个真实场景

### 4.1 任务前：检索历史经验

```sh
sh bin/evo search "awk 双文件"      # 账本口径，快
```

命中就引用，不命中就照常做——**不要为了检索而检索**。

### 4.2 任务后：复盘落账

只写三样东西：**目标达成没有、验收标准满足没有、失败归因给谁**。
不值得记就不写。记账不是 KPI。

### 4.3 失败归因

失败条目比成功条目值钱。落账时把「工具错 / 假设错 / 信息缺」写清楚，否则下一轮会重犯同一个错。

### 4.4 经验升规则

同一类失败出现第二次，就该把它从 `exp` 升级成 `rule`，并进 `SKILL.md` 的 H 硬约束表——**规则是压缩过的经验**，不是另一种文体。

## 5. 命令全表

### 5.1 `bin/evo` 入口（16 个）

| 命令 | 作用 | 何时用 |
|---|---|---|
| `evo version` | 打印版本 / 根路径 / 账本路径 | 排障第一步 |
| `evo store sync` | 账本 → `store/journal.tsv`（幂等，含近重复去重） | 改完账本 |
| `evo store show [n]` | 查看结构化账本（默认 10 条） | 抽查落账质量 |
| `evo index build` | `journal.tsv` → `index.tsv` | sync 之后 |
| `evo index stats` | 分域统计 | 看索引健康度 |
| `evo index check` | 结构 + 新鲜度校验（门禁 C12 复用） | 怀疑索引过期 |
| `evo search "<词>"` | 加权检索，HIT rc=0 / MISS rc=3 | 任务前检索 |
| `evo search-eval` | 账本口径检索评测（Top-1 / MRR / MISS） | 改检索逻辑后回归 |
| `evo self-test` | 脚本存活自测（语法/入口/冒烟/git/残留） | 每次改动后 |
| `evo lint` | 表式账本校验（类型 / 空字段） | 账本格式出错时 |
| `evo bundle` | git 历史冷备（`data/backup/*.bundle`） | 每周 / rootfs 重建前 |
| `evo journal` | → `journal-add.sh` | **已废弃**，见 7.1 |
| `evo route` | → `route-cache.sh`（ROUTE 命中统计） | 调检索策略 |
| `evo enum` | → `enum_merge.sh`（枚举轨合并） | 条目枚举去重 |
| `evo rotate` | → `rotate-journal.sh`（账本轮转） | 账本超过检索性能阈值 |
| `evo bridge` | → `bridge-journal.sh`（跨对话桥接） | 跨对话采集 |

> **已知文档漂移**：`bin/evo` 无参时的 usage 只打印前 11 个，`route/enum/rotate/bridge/journal` 五个未列出（功能可用）。列为待修项。

### 5.2 直接调用的脚本（`data/cmd/`，23 个，未全部挂到 `evo`）

| 脚本 | 作用 | 备注 |

## 6. 数据在哪 / 备份 / 迁移 / 卸载

### 6.1 三个文件就是全部状态

| 文件 | 角色 | 能否手改 |
|---|---|---|
| `<插件目录>/com.yg.evo/journal.md` | **账本真身**（表格） | 可以，改完必须 `store sync` + `index build` |
| `data/store/journal.tsv` | 结构化视图（派生） | 不要手改，会被 sync 覆盖 |
| `data/store/index.tsv` | 检索索引（派生） | 不要手改，`index build` 会重建 |
| `data/backup/*.bundle` | git 历史冷备 | 只读 |

派生文件全部可重建——**真正需要备份的只有账本**。

### 6.2 备份

```sh
sh bin/evo bundle            # git 历史 → data/backup/*.bundle
cp data/journal.md /path/to/backup/journal-$(date +%F).md
```

异地备份要**整目录同步**（脚本 + 数据同版本），只同步数据会让 `restore.sh` 假红。

### 6.3 迁移到新机器

1. 拷账本 `journal.md`
2. 新机器安装（见 §2）
3. `store sync` + `index build`
4. `self-test` 判 `FAIL=0`

### 6.4 卸载

删目录即可。没有服务、没有注册表、没有守护进程、没有残留配置。

## 7. 故障排查（全是实测坑，不是猜的）

### 7.1 写了经验但检索不到

最常见根因：**读写不同源**。`bin/evo journal-add` 写的是 `data/journal.md`（分发模板），而 `store sync` 读的是插件账本 → 写进去也不进索引。

**正解**：用 `evo_reflect`（插件内）或直接编辑真账本；`journal-add` 已废弃。

### 7.2 `search` 返回 MISS，但条目明明在账本里

按顺序查：

1. 忘了 `index build`（`index check` 会报新鲜度）
2. **folder 分类缺失**——这是历史 rank=0 的主因，不是检索坏
3. 查询词与条目用词完全无交集（中文长句可试 2-gram 拆词）

### 7.3 `self-test` 有 WARN

WARN ≠ 故障。公开快照态下「无账本 / 无 git / 无 bundle」三条必现，属预期。**只看 `FAIL=0`**。

### 7.4 三方不一致（账本 ≠ store ≠ index）

```sh
sh bin/evo store sync && sh bin/evo index build
```

若刚跑过 `journal-commit`，它可能追加了自检条目 → 再跑一次即收敛（见 3.4）。

### 7.5 `git init` 在 `/sdcard` 上失败

`sdcardfs` 走 FUSE，git 写 `objects/` 会 `No such file or directory`。仓库要建在 proot 内部（如 `/root/evo-git`），用 `bundle` 单向回写。

### 7.6 `read_file` 报「工具结果缺失」

中文路径下的已知缺陷，不是文件不存在。改用 `terminal` 的 `sed` / `cat`，或 `grep_code`。

### 7.7 钩子不生效（密钥守门被静默跳过）

`sdcard` 上 `chmod` 无效，仓库内钩子拿不到执行位，**git 不报错、不告警，直接放行**。要在 git-dir 里放转调壳：

```sh
GITDIR=$(git rev-parse --git-dir)
printf '#!/bin/sh\nT=$(git rev-parse --show-toplevel 2>/dev/null || true)\nexec sh "$T/.githooks/pre-commit"\n' > "$GITDIR/hooks/pre-commit"
chmod +x "$GITDIR/hooks/pre-commit"
git config --unset core.hooksPath
```

### 7.8 打包体积每轮都不一样

`pack.sh` 用三轮等长收敛；只跑 `--fast` 单轮会看到体积波动，属正常。发布前跑完整三轮。

## 8. 已知限制（诚实版）

- **不跑公开基准**：只有 10 题样例集（Top-1 8/10），无 LOCOMO / LongMemEval
- **规模未压测**：几十条账本很顺，500+ 未验证
- **单机单用户**：无并发、无多租户
- **写入靠纪律**：不自动提取经验
- **无 SDK / API**：给人用，不是给程序调
- **源码树不可移植**：见 §2 末尾
